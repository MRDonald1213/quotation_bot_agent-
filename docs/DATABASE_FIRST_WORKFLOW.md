# Database-first email processing

The normal Gmail and web source-reading pipeline routes parsed source text before extracting values. All plausible databases are processed independently. Routing uses whole-token overlap against configured database name, description, category, routing aliases and schema metadata. Generic terms such as supplier/name/price/currency do not qualify a database on their own. A score of at least 3 qualifies a candidate; this is a deterministic routing score, not a probability. There is no single-winner tie gate. Configure database purpose and routing aliases to reflect the documents it accepts.

Each candidate gets its own schema snapshot, values, exact source snippets, missing required fields, issues, and approval/import status. Literal labelled values are parsed deterministically; prose and remaining fields use structured output from configured local Ollama. Invalid types, conflicting labelled values, ungrounded model results, oversized contexts and source parse errors prevent approval. Model failure is isolated to that destination. No values are silently borrowed from supplier records. Unknown values remain null.

Quotations displays proposals grouped by source, with individual Approve, Import and Reject controls. Only validated complete proposals can be approved. Import is separate and requires that destination's approval. Source/schema changes require reprocessing. Imports are serialized and exact-row retries do not append duplicates. Reprocessing identical sources/schemas reuses proposals and preserves decisions. Known Gmail-thread replies are processed against the original destination schemas with original source context retained. Unknown/ambiguous legacy replies retain existing review handling. External emails still require explicit human SEND.

Schema v10 adds destination_proposals without altering legacy quotation/action tables. Existing canonical quotation review and comparison remain available. Generic destination fields do not automatically become comparison facts: use the connected database assistant for schema-backed records. The older canonical document-processing API/CLI remains available for compatibility; the normal web Read action and Gmail path use database-first extraction.

API: GET /api/destination-proposals; POST /api/destination-proposals/{id}/approve, /reject, /import. Existing supplier-quotations process/analyze endpoints return all proposals. CLI: freight proposal process <intake-id>, freight proposal list, freight proposal decide <proposal-id> approve|reject|import. All use the same service.

Automated checks cover multi-destination extraction, independent approval/import, repeated import, no match, schema changes, isolated model failure, grounding, invalid types, and known-thread replies. No live Gmail delivery or live Ollama inference is used by these checks.

Verified: 114 automated tests passed. Browser verification at 1280 × 900 confirmed grouped destination proposals, independent approval, no horizontal overflow, and zero JavaScript errors. Tests use isolated temporary data and no live Gmail or Ollama.

Workspace cleanup: prior local email messages, source attachments, intake records, proposals, quotation history, and workspace copies were cleared from the configured SQLite workspace. Supplier CSVs, database connections, Gmail account authorization, and OAuth files were preserved. A mailbox receive cutoff now excludes inbox email older than the reset time. Gmail auto-classifies incoming email before routing; only verified quotations enter the quotation dashboard.

The Mailbox page refreshes active processing status every 2.5 seconds. Notifications combines incoming-email status, destination proposal state, and recent recorded user actions, and refreshes live. Manual upload/open/download controls are removed from the normal receiving interface.

Gmail attachment extraction supports PDF (selectable text plus macOS Vision OCR for image-only scans), DOCX, XLSX, CSV, TXT and EML directly. Legacy DOC/XLS, RTF, ODT and Pages use an installed local LibreOffice converter, with Pages PDF-preview extraction first. Failed conversions are recorded with a readable reason and stop automatic routing so an unreadable attachment cannot be mislabeled as an unrelated email. Google Docs links in message bodies are not fetched; Google Drive authorization is not part of the current Gmail scope.

When deterministic routing finds no plausible database, a constrained local Ollama routing agent evaluates all configured database descriptions, categories, aliases and schemas and returns every plausible destination. It still requires relevant routing metadata; if the model is unavailable, the existing keyword candidates are retained and the outcome reports no destination rather than guessing.
